Runtime derivative
-------------------

Downscaled from the source 1K maps to 512x512 (diff/disp/nor_gl/rough/spec)
via Blender 5.2 (--background --python), not ffmpeg — ffmpeg's EXR decoder
doesn't implement single-channel "Gray DWA" compression, which the rough
map uses; it silently decoded to all-zero pixels instead of erroring, only
caught by sanity-checking pixel values before trusting the output. Blender
has full native OpenEXR support and was used for both EXR maps (nor_gl,
rough) plus the two 16-bit PNG maps (disp, spec) for a consistent pipeline;
diff was kept in JPEG (via ffmpeg) rather than PNG since it's a photographic
albedo map with no need for lossless precision, and JPEG is far smaller for
that kind of content (Blender's own image export only writes PNG).

nor_gl and rough colorspace was set to Non-Color before saving (no sRGB
curve applied) — verified by sampling raw pixel values before/after
conversion; disp/spec were already non-color 16-bit source data.

diff was further color-normalized (2026-07-23) against forest-ground-04
and marble-cliff-03's diff maps — the three come from different Poly Haven
photo shoots (luminance ranged 0.29-0.51 across them, rocky_terrain_02
itself skewed strongly olive/yellow with a suppressed blue channel) and
looked visibly inconsistent once blended into one TerrainMaterial. Each
diff map's mean/std (per RGB channel) was blended 65% toward the
three-way average via a NumPy/Pillow script (Reinhard-style statistical
color transfer) — moves each texture's overall tone/contrast toward a
shared middle ground while leaving per-pixel detail untouched. Only diff
went through this — normal/roughness/displacement maps are directional or
data, not color, and would be corrupted by a tone transform.
